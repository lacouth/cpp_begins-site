    8. Iteradores, algorithm e lambdas¶

    Vídeos

    07 - Strings e a biblioteca algorithm · 12 - Vector Parte 5 (usando algorithm)

    O que você escreveu à mão, agora em uma linha¶

    No capítulo 5 você escreveu seis algoritmos com for e if. Todos eles já existem na biblioteca padrão, testados e mais rápidos que qualquer versão escrita à mão:

    Você escreveu no capítulo 5 A biblioteca já tem
    busca_linear std::find
    maior_elemento std::max_element
    conta_pares std::count_if
    media (a soma) std::accumulate
    troca std::swap
    bubble_sort std::sort
    busca_binaria std::binary_search

    Lado a lado, o conta_pares daquele capítulo:

    int conta_pares(const std::vector<int>& v) {          // capitulo 5
    int total = 0;
    for (int x : v) {
        if (x % 2 == 0) {
            total++;
        }
    }
    return total;
}

// a mesma coisa, agora:
int total = std::count_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });

    A troca não é só de tamanho. std::sort não é um bubble sort com nome bonito: ele é assintoticamente melhor (n·log n contra n²), o que para dez mil elementos é a diferença entre cerca de 130 mil comparações e cerca de cem milhões. E std::find não tem como errar o limite do laço.

    Daqui para a frente, use as versões prontas. O capítulo 5 existiu para que você saiba o que elas fazem por dentro — e para que, quando uma delas se comportar de um jeito estranho, você tenha onde se apoiar para entender.

    Iteradores, rapidamente¶

    Um iterador é um objeto que "aponta" para um elemento dentro de um container e sabe andar para o próximo. Você já usa a ideia todo dia em C, na forma de um ponteiro andando por um vetor:

    for (int* p = vetor; p != vetor + tamanho; p++) {
    printf("%d\n", *p);
}

    std::vector (e todo container da STL) oferece .begin() e .end(), que funcionam de forma parecida:

    std::vector<int> v = {10, 20, 30};
for (auto it = v.begin(); it != v.end(); ++it) {
    std::cout << *it << " ";   // *it desreferencia, igual ponteiro
}

    Na prática, você raramente escreve esse laço na mão — é exatamente o que o range-for (for (int x : v)) faz por baixo dos panos. Mas entender que existe é importante porque as funções de <algorithm> (próxima seção) trabalham recebendo um par de iteradores (begin, end), não o container inteiro — isso permite que a mesma função de <algorithm> funcione em vector, string, map, set, etc.

    Lambdas: funções "descartáveis" no meio do código¶

    Antes de <algorithm>, você precisa saber escrever uma lambda — uma função anônima, definida no lugar onde vai ser usada. É a resposta do C++ para "quero passar um comportamento como argumento", algo que em C você fazia com ponteiro de função:

    // em C: ponteiro de funcao
int compara(const void* a, const void* b) {
    return *(int*)a - *(int*)b;
}
qsort(vetor, tamanho, sizeof(int), compara);

    Em C++, a lambda pode ser escrita ali mesmo, sem precisar de um nome nem de arquivo separado:

    auto dobro = [](int x) { return x * 2; };
std::cout << dobro(5) << "\n";  // 10

    Anatomia de uma lambda: [captura](parâmetros) { corpo }.

    • [] — não captura nada do escopo ao redor.
    • [x] — captura x por cópia (a lambda enxerga o valor de x no momento em que foi criada).
    • [&x] — captura x por referência (a lambda enxerga o x de verdade, inclusive mudanças depois).
    • [&] — captura tudo do escopo ao redor por referência; [=] — tudo por cópia. Evite essas duas formas "coringa" em código para os outros lerem — prefira ser explícito sobre o que a lambda usa.
    int limite = 5;
auto maior_que_limite = [limite](int x) { return x > limite; };
maior_que_limite(10);  // true
maior_que_limite(3);   // false

    <algorithm>: comportamento pronto para percorrer containers¶

    Em vez de escrever um laço na mão toda vez, <algorithm> oferece funções genéricas que recebem begin()/end() (e, em vários casos, uma lambda dizendo o critério):

    #include <algorithm>
#include <vector>
#include <numeric>   // para std::accumulate

std::vector<int> v = {5, 3, 8, 1, 9};

std::sort(v.begin(), v.end());
// v agora e {1, 3, 5, 8, 9}

std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
// ordem decrescente: {9, 8, 5, 3, 1}

auto it = std::find(v.begin(), v.end(), 5);
bool achou = (it != v.end());

int quantos_maiores_5 = std::count_if(v.begin(), v.end(),
                                        [](int x) { return x > 5; });

bool algum_negativo = std::any_of(v.begin(), v.end(),
                                    [](int x) { return x < 0; });

bool todos_positivos = std::all_of(v.begin(), v.end(),
                                     [](int x) { return x > 0; });

int soma = std::accumulate(v.begin(), v.end(), 0);
// 0 e o valor inicial do acumulador

std::vector<int> dobrados(v.size());
std::transform(v.begin(), v.end(), dobrados.begin(),
                [](int x) { return x * 2; });

    Note o padrão comum: iterador de início, iterador de fim, e (quando precisa de um critério) uma lambda. Isso é o que torna sort, find, count_if etc. genéricos — a mesma função std::sort ordena vector<int>, vector<std::string> ou vector<Aluno> (com a lambda certa), sem precisar de uma versão para cada tipo.

    <algorithm> também funciona em std::string¶

    std::string é, por baixo, um container de char — então os mesmos algoritmos se aplicam:

    #include <algorithm>
#include <cctype>

std::string texto = "Programacao";

std::reverse(texto.begin(), texto.end());
// "oacamargorP" -- e aquela funcao "inverte" que voce escreveu na mao na Lista 01

std::sort(texto.begin(), texto.end());
// ordena os caracteres

std::transform(texto.begin(), texto.end(), texto.begin(),
                [](unsigned char c) { return std::toupper(c); });
// converte tudo para maiuscula -- a mesma logica do exercicio "maiusculo" da Lista 02

    Perceba: os exercícios que você resolveu "na mão" nas listas 01 e 02 (inverter string, converter para maiúsculo) agora têm uma versão de uma linha usando <algorithm>. Não é acaso — aprender a versão manual primeiro é o que torna óbvio o que <algorithm> está economizando.

    Erros comuns¶

    "error: no matching function for call to..." ao usar lambda em std::sort — confira se a lambda de comparação retorna bool e recebe dois parâmetros do tipo do elemento (ex.: [](int a, int b)), nunca um só.

    Esquecer #include <algorithm> ou #include <numeric> — sort/find/count_if/transform vêm de <algorithm>; accumulate vem especificamente de <numeric>. Mensagens de erro tipo 'sort' is not a member of 'std' geralmente significam um include faltando.

    Capturar por referência ([&]) uma variável que sai de escopo antes da lambda ser chamada — se você guardar a lambda para usar depois (não é o caso mais comum nas listas, mas aparece em código real), uma referência capturada pode "morrer" antes da lambda ser chamada. Prefira captura por cópia ([x]) quando não tiver certeza.

    Resumo¶

    • Iterador é um "ponteiro genérico" (begin()/end()); range-for usa iteradores por baixo.
    • Lambda: [captura](parâmetros) { corpo } — função anônima definida no lugar de uso, o equivalente moderno a passar um ponteiro de função.
    • <algorithm> oferece operações prontas (sort, find, count_if, any_of, all_of, transform) que recebem um par de iteradores e, quando precisam de critério, uma lambda.
    • <numeric> tem accumulate para somar/reduzir uma sequência.
    • Os mesmos algoritmos funcionam em std::string, porque ela também é um container de char.
